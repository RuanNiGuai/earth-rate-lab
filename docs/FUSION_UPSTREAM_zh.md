# 上游移植与融合算法取舍（2026-11-11）

本次采用“现有 VQF／休眠恢复框架＋确定的数值修复＋温度输入确认”。新 VQF 实验策略并非整体理论优于旧版；第三种 Fusion AHRS 在部分干扰下更好，也存在反例。目前没有外部姿态真值和板上负载对照支持替换主算法。本次代码、离线实验和候选固件均不代表已刷入设备。

## 温度的两层确认

采集区间保持 **15–43°C、每 0.2°C 一个桶**，43°C 为分桶上界；运行曲线保持原 113 节点、0.25°C 网格。两者用途不同。

1. **读数层**：启动、超过 1 秒没有接纳温度，或新读数比上次接纳值跳变超过 1°C，先暂存。至少 3 次采集、跨越至少 100ms，候选最大最小值相差不超过 0.2°C 才接受。正常缓慢变化直接接受。同一个 FIFO 内多条陀螺仪数据不重复计数。
2. **温度点零偏层**：已有的“大幅零偏差异需 3 个一致静置窗口确认”机制保留，并增加回归验证。这与读数层的 3 次温度采集不同。

明确的硬件无效标记、通信失败、非有限值、越界读数，重复再多次也不升级成有效温度。读数层的有效性范围为开区间 −20–60°C，不把真实 0°C 当成无效标记；是否能建表还要再过 15–43°C 范围和静置／姿态门槛。

待确认或无效期间，不更新温度时间戳，不推进温度低通；运行补偿最多保留上次值 1 秒，之后按原逻辑回退到静态零偏。校准窗口、原始归档及 F04 温度立即标记不可用，不将旧温度当成新证据。确认新平台后立即重置温度低通起点；正常变化时，校准配对的是接纳的原始温度，运行补偿使用 500ms 低通值，避免将低通滞后的温度记入表。

1°C、0.2°C、100ms、1 秒属于工程初值，仍需实机热循环验证。持续且一致的错误但合法读数仍可能通过确认；该机制不能代替传感器硬件诊断，也不能自动修复以前已写入的受污染点。

## 新 VQF 实验策略的条件与风险

| 策略 | 可能的收益 | 不稳定的机制／条件 |
|---|---|---|
| 自适应倾角时间常数 | 转动时快速校正，强加速度时降低信任 | 加速度模长接近 g 并不说明只有重力；转动和位移并存时可能误加权。系数状态变换、低通精度、变化速率也会影响连续性 |
| 固定 tau 的独立输出观测器 | 将输出倾角平滑与自适应内部观测分离 | 仍共享陀螺仪与零偏，不能消除错误航向零偏；休眠必须保存它自己的状态 |
| 自适应零偏／温度预测 | 有充分姿态激励及可信静止段时，更快跟踪残余偏置 | 温度与时间、真实慢转混淆，可能再次学习温补表已处理的部分；相邻验证块也可能高度相关 |
| 放宽静止切换判据 | 动作停止后较快恢复零偏估计 | 匀速慢转的方差很低，可能被当成静止；绕重力轴慢转尤其无法仅由加速度排除 |
| 快速静止恢复 | 按滤波器尾迹预测等待时间，减少不必要等待 | 假设采样率、滤波参数和有效样本数正确；漏样、时间基准错配、停转过渡会破坏模型 |
| 完成周期的零偏观测 | 真正闭合的姿态周期提供额外约束 | 周期性动作不必回到原朝向，可能有净航向变化；缺帧、乱序、周期边界错配会制造虚假闭合误差 |

上游曾以“not stable”为由关闭多项实验功能；这只是作者的状态说明，不足以认定唯一原因。独立输出观测器在上游仍有默认开启路径，不能说所有实验行为都已关闭。这里依据各策略的观测条件决定不整套开启，而非仅依据提交标题。

## 是无线缺漏乱序，还是算法问题

融合在追踪器 MCU 内、姿态无线发送之前运行。单纯丢失或乱序的接收端姿态包，能造成画面卡顿、跳到最新姿态，或在接收端不拒绝旧包时短暂回退，**通常不会直接修改设备里的 VQF 状态**。

直接影响融合的路径包括：传感器 FIFO 漏样／错误拒包、传感器样本顺序、采样率切换与固定 Ts 不一致、陀螺仪和加速度不同步、低通／零偏状态错误恢复，以及错误零偏观测。无线工作造成 CPU 抢占、继而 FIFO 堆积或溢出，是可能的间接路径，需要同时记录 FIFO 统计、融合样本数和接收序号才能确认。F04 无线窗口缺失率不能直接当作 MCU 融合漏样率。

本次构造的匀速例子：30°/s 转 2 秒，完整数据为 60.000°；融合输入缺 25% 且仍按固定步长积分，为 45.000°。仅在本例的匀速假设下，按正确经过时间积分可恢复 60.000°。任意变速或多轴运动，扩大下一样本的 dt 无法恢复丢失的历史，不能作为通用补帧算法；更不能把 FIFO 批次到达主机的时间间隔当作每条样本的采样间隔。

## 第三种算法的实际对照

使用仓库已有 **x-io Fusion AHRS** 作为第三种算法候选，对照当前 VQF 核心；另外各跑一条冻结在线零偏的分支，用来分离姿态算法与零偏学习的影响。运行：

```sh
python tools/fusion_scenarios.py --out fusion-scenarios.json
```

脚本使用真实 C 核心、100Hz、30 秒初始静止；无噪声、无磁力计，不包含本项目外围门控、Earth 修正、硬件调度，也**不代表完整上游实验策略的回放**。VQF 使用本项目参数，Fusion 使用显式列出的常规增益和拒绝设置，未做各算法的最佳参数搜索。JSON 记录源码哈希。

| 构造场景 | VQF，在线学零偏 | Fusion AHRS，在线学零偏 | 判断 |
|---|---:|---:|---|
| 持续 60 秒输入 z 轴 0.2°/s，重力不变 | 输出航向 2.124° | 1.591° | 若真实静止，这是剩余漂移；若真实慢转，真值为 12°，两者都把运动大量吸收成偏置 |
| 相同输入，冻结在线零偏 | 12.000° | 12.000° | 保住慢转，同时也保留了静止偏置；并非全面改善 |
| 5 秒线加速度使合加速度偏转 20°，模长仍为 g | 峰值倾角误差 13.373° | 0.000° | Fusion 的创新量拒绝在此例有优势；并非当前整机门控的比较 |
| 相同干扰持续 60 秒 | 最终倾角误差 20.103° | 20.005° | Fusion 的恢复策略最终也接纳干扰，短时优势不能外推到长期 |

两种物理情形产生完全相同的 IMU 输入时，EKF／误差状态 EKF／EqF 也无法仅靠换算法保证分辨。它们便于表达协方差、变步长和创新量门控，但增加参数和 MCU 成本；错误的静止／周期约束仍会导致错误估计。10 台在校准夹具上可以使用刚体约束，穿戴在不同肢体后不再是同一刚体，不能沿用该约束消除航向不确定性。

因此当前保留 VQF 并修复明确问题。下一步有价值的算法实验是**有界的观测可信度／创新量加权，配合保守零偏更新**，优先比较短时加速度拒绝、误判后恢复和慢转保留；尚不把它称为已实现或必然更好的生产算法。评估必须使用独立角度真值、丢样故障注入、启动／倒置／休眠恢复，并测 MCU 时延及电流。

## 其他上游功能的处理

- **统一温补网格曲线**：有价值，但本地表同时涉及采样线程、控制台查询、缓存失效和 CALWIRE 导出。暂不移入热路径；应先明确表的读写归属与代际检查，再保证缺少节点时的按需计算不阻塞采样。这次仍有 LUT→MLS 回退路径，未宣称消除其差异。
- **电源／复位事件无线发送**：接收端已有协议，追踪器尚缺发送生命周期整合；仍列入待办。应与真实休眠、重启会话及有限重试一起移植，不能仅复制发送文件即宣称诊断完备。
- **休眠准备失败后冷重启**：需要错误向上传递和硬件故障验证，不能以冷重启替代已有姿态保留恢复；自动深睡仍关闭。
- **加热、外接磁力计、其他板型**：当前 Styria Mini／无磁配置缺相应硬件或需求，不纳入本次。
- **SDK／Helper 整体升级**：涉及架构、构建链和旧 GUI 本地扩展，独立处理，保留本次冻结 SDK 和公开 CLI。

## 验证边界

主机测试执行实际温度接纳代码、ICM 温度函数、接收器配对解析与 VQF 核心。覆盖硬件无效值混入、全部 256 种包头、重复／乱序时间、真实温度平台、温度点覆盖确认、恒定输入系数切换、近倒置轴方向、600 秒协方差运行以及拒绝观测不改变姿态／零偏。既有休眠保存／恢复回归单独重跑。

主机数学库测试不是 ARM CMSIS 数值一致性证明；候选还需设备上做热循环、实际漏样、延迟、电流和整夜佩戴验收。既有校准参数、旧温度表和设备固件未由本次离线实验修改。
