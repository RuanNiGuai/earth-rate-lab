# Helper 十台连续联合校准

ARC8 页面按五步引导完成校准。正常使用无需阅读本文、安装 Python、选择工具包或手动准备时钟／分段文件；动作顺序、等待条件、失败原因和下一步均显示在面板中。本文记录实现与维护边界。

## Helper 日常入口

- **数据采集**并列提供“单台 · 全频原始数据”和“十台联合 · 稳定积分采集”。单台沿用原始样本、设备选择和 `.slimecap` 回放流程；十台使用与联合校准相同的 F04 50 Hz 积分窗口、READY、身份收据与结束清单。后者不等于全频逐样本数据。录制自动保存到独立任务目录，不修改校准会话的四份录制或求解结果。
- **温度校准**接通无线状态刷新、开启／关闭自动采集、关闭采集后备份并逐格检查温表。范围 [15,43)°C、0.2°C 桶，完整范围有 140 桶。检查包括内部缺口，不能用最高／最低温度代替覆盖率。空温表可检查但不能进入求解。详细检查后自动采集保持关闭。采集需 USB 供电、静置及外部升降温；此工具支持当前十台 0–9 号设备。
- **无线更新**使用原生 ESB OTA，支持 MCUboot 签名应用。按设备查询、固件选择、映射检查、确认更新执行。候选目录按钮打开程序旁的 `firmware-candidates/`；初次公开包不附带硬件专用固件，需要自行准备与板型、协议和启动加载器信任密钥匹配的签名应用。追踪器使用签名 BIN，接收器使用有线更新页的匹配 UF2。打开页面、导入文件不会刷写，实机验收状态见包内报告。
- **联合校准**只展开当前一步，允许点击任一步查看；成功后定位下一步。逐台误差／正反差异可展开，安装前仍展示计划数值。旧 ARC8、单机离线实验及协议诊断统一收在高级区域。

温度命令按冻结的接收器及 RF 身份逐台等待完成确认，STARTED／QUEUED 不算完成；随后回读自动采集开关，状态与命令一致才报告成功。该状态是采集开关，不是已有温表的补偿应用开关。开启中途失败或取消时，尝试关闭所有可能已开启的设备；无法确认的回滚写入日志。后台线程退出后才释放独占。温度与点数是一次读取的快照，需要时再次刷新。

## 安装与前提

解压完整 Helper 包，保留程序旁的 `calibration/` 校准运行组件；不要仅复制主 EXE。普通 Helper 功能独立于该组件。开发者仍可在折叠的高级工具里指定源码工具包和 Python。

需要同向牢固固定的十台追踪器（接收器 0–9 号），配套可靠采集固件 Tracker `_cw5_f04ack`、Receiver `_cw4_f04ack`。该组合已在实验设备部署，其他设备须先确认硬件和启动加载器兼容，不能仅更新 Helper 就获得固件端能力。准备时先核对全部身份，再读取只读快照；缺少有效 +X 地球参考、温度表或兼容协议时，界面提示先在命令页完成对应准备。

自动温度观测每次开机默认关闭。已有温表的补偿应用与自动采集独立；录制和快照期间保持自动采集关闭。温区 15–43°C、0.2°C 桶，上界 43°C 不在采样区间内。联合求解会检查四次录制的全部温度支持，缺失温度逐台报告。

## 面板的五步流程

**校准录制前请退出SlimeVR及其后台服务器。** 当前设备组合的实机对照发现同时运行会出现接收器反压和采集缺口；退出后通过READY并恢复连续数据。Windows下启动录制会检查常见SlimeVR进程／自带Java服务器并给出提示，不会自动关闭程序。自定义启动器或其他平台仍需手动确认；普通追踪不受此要求影响。

1. **准备十台**：选择接收器（仅有一台时自动选择），点击准备。会话放在操作系统用户数据目录，自动创建独立目录；可继续上次会话，也可另建一轮。核验结束不自动开始录制。
2. **X／Y／Z 正反转**：每轴录一次完整过程。所选轴竖直朝上，准备期间显示每台朝上面。全部十台方向正确且保持静止，传输至少各收到 200 个连续、新鲜窗口后才 READY。然后连续完成：静置约 30 秒 → 同向平稳转满 20 圈 → 静置约 30 秒 → 反向转满 20 圈 → 静置约 30 秒 → 结束。每圈约 2–3 秒；无需逐段点击或等待回复。
3. **地球项／g-sens 与首尾检查**：恢复 +X 朝上并记住边的方向。READY 后，同一面依次在原方向、同向 90°、180°、270°、360°静置，建议各 90–120 秒；再依次摆 −X、+Y、−Y、+Z、−Z 朝上，各约 30 秒。转换约 10 秒。建议最后回到最初的 +X 面和同一条边的原方向，再静置 90–120 秒，作为可选第 11 段；之后点结束，全程无需逐段确认。已有完整十段仍可用，延长静置不保证误差门槛通过。
4. **自动检查与联合求解**：输入实际纬度（北纬为正）。程序重新备份十台温表及原参数，自动检查四份录制、估计时钟并识别静置段，将三轴正反转与十姿态一起求解。原始加速度不合并为同一点轨迹；安装方向和各位置杆臂分别建模。
5. **比较、审阅并写入**：点击“回放比较并推荐参数”，自动读取当前会话并显示原参数、推荐参数、稳定低通、动态零偏的静置与转动回位指标。逐台决定是否更新比例；当前保留原地球项和 g-sens。勾选审阅生成计划，再恢复原始 +X 面及边的方向，重新勾选实际写入确认并点击写入。写入后手动重启十台，再核验回读。软件门槛通过不等于独立实机精度验收。

推荐计划使用已验证字段选择：新比例必须来自十台联合结果，正反差 ≤0.2%，采用原 g-sens 重算的六次积分三分量 RMS ≤7.2° 且比旧比例至少改善1%；回位 RMS 不得超过旧值+0.05°，静置 RMS 不得超过旧值×1.1+0.005°/分钟。达不到就保留该台旧比例。地球项、g-sens 按原始浮点字节保留；它们的新候选诊断单独列出，不冒充通过，也不阻止无关字段更新。无设备需要更新时不生成空计划。

高级工具不选择部分字段时，仍要求全部新 S/M/E 通过原门槛。未通过时保存 `review.md`／`review.json`，不生成计划。重新比较、准备或求解即撤销旧计划入口，失败也不恢复旧写入许可；原始数据与历史产物始终保留。继续会话会恢复当前比较及核验过的计划，写入前仍要明确确认。

回放以实际 C 融合核心运行，但 F04 窗口均值不能恢复窗内高频运动，快照也缺少已安装的加速度校准矩阵。校准与检验使用了相同录制，人工返回没有外部角度真值。稳定低通和动态零偏均为电脑端对照，参数写入不会启用这些固件算法。当前动态策略存在慢转被学习为零偏的反例，不推荐默认使用。g-sens 候选在原始加速度坐标求得，缺少设备坐标变换时不直接写入。

准备超时会在动作前退出；READY 后不会因发现某个姿态或短时质量异常而主动打断整轮。用户结束时排空队列并核对十台结束清单。切换页面不结束任务；关闭程序或取消会等待后台收尾，设备访问保留到工作线程结束。

录制准备失败会列出具体设备及原因：数据不连续／不足／过期、朝向错误或仍在转动，并保留诊断目录。已修复F04暂停普通姿态后，主HID的零超时读取仍阻塞、连带拖住校准数据读取的问题；不以放宽READY门槛绕过缺口。

Windows 短暂占用进度文件时，程序会跳过这一帧界面进度并在后续刷新，不再因 `progress.json` 或 `live.json` 的替换遇到 WinError 5／32／33 而中断录制。会话与结果保存仍有限重试，失败必须报错；原始数据写盘错误也不会被忽略。收尾保存失败仍释放设备连接。进度暂时不刷新不等于数据停录。

## 自动识别与失败处理

重复点击写入会先核对全组快照：已是该计划目标值的设备只读回核验，不再写一次；仍为原备份值的设备才写入。未知变化或部分写入的中间状态仍会阻止本次写入，需先检查并恢复备份。本次失败只回滚本次触及的设备，不撤销先前已成功的设备。结果保存并绑定计划哈希；读回核验不等于重启持久化验证。

无线更新兼容 OTA v1 及当前 ARC8 v2。v2 追踪器使用匹配 Styria 板型的 MCUboot 签名 BIN；接收器与追踪器协议必须匹配。完成传输、校验及接受激活后，当前固件仍需手动重启，Helper 会明确提示，再查询核对固件版本。此状态不表示已经验证新固件启动。

录制保存每个约 20 ms 窗口的高频陀螺累计角、加速度均值、温度、序号与设备时间，**不是只记录首尾两个点**。它也不是逐个高频原始采样，窗口内部的锥运动无法完全恢复，因此要求平稳转动。

先以到达延迟下包络初始化时钟，再用十台共同角速度变化细化相对对齐；不会把 USB 到达时刻直接当采样时刻。按十台共同静止条件识别区间，边界留出余量。缺少静置、选错轴、三轴正反转时同向转两遍、角度明显不符、夹具松动、时间或传输异常均拒绝进入下一步。自动检测不能独立证明用户恰好转了 20 圈。

十姿态推荐按面板顺序操作，但检查依据是实际姿态覆盖：前五段保持 +X 朝上，每次约转 90°，第五段回到起始方向；后五段只需 −X、+Y、−Y、+Z、−Z 各一次，顺序可不同。前五段允许中途反向，但须在扣除常量零偏和时间漂移后仍能辨识两个地球水平分量；反复只走两个航向不能通过。三个不同航向的回环可能可用，信息量与四航向不相同，仍需通过求解后的残差和可辨识性门槛。程序按原时间线积分，不重排或补造数据。

可选末尾返回段参与常量零偏／时间漂移及地球／g-sens 的联合拟合，后半段留出验证；报告显示积分姿态的首尾闭合角。只有同一面朝上不足以证明航向返回，需同时恢复原先边的方向。含第 11 段时，首尾积分姿态角及各台重力方向夹角均须 ≤3° 才能生成安装计划。该检查是同一轮数据的一致性边界，不是独立角度真值，也不把末姿态强行设为零来掩盖漂移。

长时间静置的时钟对齐按实际运动样本归一化，不再要求运动占整段录制的 5%。延长静置仍需足够清晰的姿态转换；若录制提前中止、缺少后续动作，已保存窗口不能补造为完整录制。对应步骤重录即可，其他有效步骤保留。

升级组件后点击“继续上次会话”，会自动重新分析最近一次被旧规则拒绝的十姿态录制；先核对原文件哈希，并保留旧失败记录。同一分析版本只重试一次，缺面、缺口等真实质量问题不会因升级变成通过。

重录保留旧文件及失败尝试，但撤销该步骤的通过状态和旧求解／写入产物指针。配置绑定四份原录制及各台数组、快照的 SHA256；文件改变后拒绝继续安装。

传输检查失败会明确显示设备编号、缺失窗口数和比例、最长连续缺口，以及设备发送队列溢出／传感器无效窗／尾部丢弃、结束确认和接收器丢弃情况。“继续上次会话”保留最近失败原因，不再把读取失败会话显示成录制完成。设备队列丢失的数据不能靠修改文件恢复；若缺口只发生在静置，可另外评估剩余真实观测是否足够用于诊断，但不会因此把原始传输检查改成通过。

求解采用自动收敛停止：至少4轮，连续3次参数和残差变化都足够小才通过，默认30轮仅作上限。求解过程记录当前轮次与阶段；所需时间取决于录制长度和数据质量。达到上限仍未收敛会显示中文原因及诊断报告路径，录制数据保留；不能直接写入这个结果。高级离线求解允许保留诊断，但生成安装计划时同样核验完整收敛记录。旧版本求解结果需重算，无需因此重录原本完整的数据。

三轴长旋转的全部窗口现与十姿态转换共同参与时钟、角运动及不同位置杆臂拟合，并反馈比例／g-sens；静置异常自动降权。新增地球信号可辨识性检查，避免仅因拟合固定了理论地球幅值就误判成功。停止阈值、信息量门槛及留出验证范围见[求解说明](JOINT_SOLVER_zh.md)。

连续反馈已修正比例缩小会连带缩小残差的偏差，长旋转曲线间隔也由100 ms改为20 ms。旧数值修订的结果须重算，原录制无需因此重录。报告将20圈残差分为沿旋转轴和横向两部分；原先的“三分量联合角度RMS”不等于手工放回误差，也不等于独立验证精度。

## 正反转分析与固件候选

两方向共同拟合当前固件可使用的每轴单一比例系数，同时独立报告正、负角速度候选系数、相对差异、每段积分角、温度范围、时间、平均转速和前后静置零偏。所有连续窗口保留，便于区分稳定方向差异、温漂、转速、圈数误差和操作方式。

目前计划门槛：正反转相对差异 ≤ **0.2%**；共同角度残差 RMS ≤ **7.2°**（20 圈的 0.1%）；地球航向回环 ≤ **3°**；各台 Earth 训练／留出 RMS ≤ **0.001°/s**，g-sens ≤ **0.006°/s**，另要求传输、温度支持与物理范围通过。这些是候选筛选标准，尚不代表实测精度保证。

方向差异过大时保留完整结果，用于判断固件是否应支持分方向系数，不把候选强塞进现有三浮点 scale 字段。本次没有增加正负系数协议、改变融合逻辑或刷机。若后续数据证明差异可重复，需连同过零行为、存储版本、协议及回滚一起设计。

## 高级与旧数据

手工导入、旧设备累计存档和显式时钟／分段入口保留在高级工具。旧存档是累计观测而非完整窗口历史，不能冒充新流程的正反转连续录制。旧数据仍可按[联合求解文档](JOINT_SOLVER_zh.md)处理。

离线检验与打包方法见[构建文档](BUILD_zh.md)。已有用户通过Helper完成四份实机录制，并用现有数据完成十台联合求解；顺序不同的十姿态可恢复，原始文件哈希保持。全新 S/M/E 候选未通过全部安装门槛；分字段推荐计划只更新通过比较的比例，保留旧 M/E，已完成十台写入及再次读回。最新比例更新尚待明确重启持久化、独立精度及首次使用体验验收，详见[当前状态](STATUS_zh.md)。
