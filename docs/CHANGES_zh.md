# 相对 jitingcn 上游：新增能力与既有功能修改

本页直接比较 **Earth Rate Lab 已发布提交 `6f8f6b77cf60bad262f155e3dee9ff552995d715`** 与 **2026-11-13 核实的 jitingcn 上游源码**。上游 Tracker 为 `a9b441c`、Receiver 为 `109a4d2`、VQF 为 `6d68ad6`、Helper 为 `2872946`（0.4.6）。完整提交、逐项源码入口和复现方法见[上游文件对照](UPSTREAM_DIFF_zh.md)。本地 CW、ARC、F04 的中间版本只用于[实验历史](EXPERIMENTS_zh.md)，不充当本页的上游。

本项目沿用 SlimeNRF 的固件、无线框架、VQF 和桌面 Helper，在这些已有功能上修改采样、补偿、传输与操作流程，并增加十台联合校准。**“上游已有”不表示“本项目未修改”；以下同时说明继承的基础和实际改动。**

后续更新：本页固定提交的对照表保留原审计范围。2026-11-13 在此基础上完成稳定低通、状态版本和加速度快照等[精度修正](ACCURACY_CANDIDATE_zh.md)，并已[部署十台 CW6](DEPLOYMENT_20261113_zh.md)。新增[独立腕部复测](WRIST_RETEST_20261113_zh.md)及[相对不校准的逐项比较](CALIBRATION_ABLATION_20261113_zh.md)；它们没有计入旧提交的文件统计，也不是与上游固件的性能 A/B。

## 已有功能具体改了什么

| 功能 | 上游当前实现 | 本项目修改后的行为 | 作用、代价与限制 |
|---|---|---|---|
| 陀螺灵敏度／比例校准 | 已有手动比例设置、`sens auto <轴> [圈数]`、采样时间积分和 Helper 静止／逐轴引导 | 增加连续正反转记录与诊断；十台同夹具完成三轴各正反20圈，再结合多姿态记录共同求解。固件仍使用每轴一个比例 | 保留原有校准能力，扩大为可审阅的整组流程；正反差异不等于已支持正负两套运行系数，必须数对圈数并固定夹具 |
| 温度输入与补偿 | 已有温度有效性检查、低通、T-Cal、MLS/LUT、开机／运行偏置处理和自动采集开关 | 增加温度跳变的三次／100ms确认；采集用接纳的原始温度，补偿用滤波值；无效时立即停止给采集提供温度，补偿最多沿用旧值1秒 | 防止孤立错误读数污染窗口，代价是确认延迟；上游也有检查，不能写成“上游不验证温度” |
| 温表采样与存储 | 默认10–45°C、0.5°C采样间隔，LUT为0.5°C网格；已保存实测均温，并按升／降温方向混合零偏 | 本配置改为 `[15,43)`°C、0.2°C采样桶及0.25°C LUT；同桶混合时温度与零偏使用同一权重，大幅不一致用多个静置窗口确认；增加固定参考姿态／新鲜度门槛及 CALWIRE 互斥 | 适配本批设备的实验温区，温区比上游默认窄；更密的表不保证更准。实测均温、自动开关及温补本身均非本项目首创 |
| VQF 融合与输出 | 已有 VQF 及零偏估计；当前上游库还提供 observer／bias policy hooks，Tracker 有对应应用策略 | 在本项目较早的融合框架上接入 Earth pair、加速度观测门控、参考姿态及休眠状态保存；选择性移植数值修复，不整套替换为当前上游状态布局 | 保留本项目地球项与恢复路径，但不能声称等同于最新上游融合。固定提交中稳定低通仅为主机原型，后续 CW6 已部署 |
| 原始数据采集与无线重传 | 已有原始传感器采集、校准快照、单目标 ARQ 丢包请求与重传；也有批量采集入口，批量路径不保留单目标 ARQ 历史 | 保留单台原始采集，增加十台约50Hz F04积分窗；按设备／启动／会话／序号／CRC确认接收器入队，未确认窗保留并重试，结束清单核对生成与落盘 | 新增的是整组积分窗协议及完整性判据，而非首次实现无线采集或重传；窗内高频信息不保留，RAM仅约1.28秒，ACK不代表主机落盘 |
| TDMA 与普通追踪调度 | 已有 TDMA、时钟同步、PING/PONG、普通姿态输出及采集模式 | F04使用专用较宽时隙并暂停普通姿态，保留控制／心跳；本分支修改采集重同步退避、PONG身份／序号匹配和接收器时钟回退处理 | 服务十台校准的完整性；停止后恢复普通姿态，未把普通追踪全部改为可靠重传。没有同条件上游时延或功耗对照 |
| 参数设置、快照与回读 | 已有 `sens`／`tcal` 等命令、原始采集校准快照、温表备份接口；Helper会比较逐轴校准前后的可读值 | 新增 CALWIRE冻结快照和限定字段写入；主机按完整身份／CRC／证据哈希全组预检，逐字段写S/M/E、回读并记录回退；已达到目标的设备只核验 | 扩展为整组参数计划和可恢复日志；三个NVS提交不是原子事务。温表／归档备份不意味着允许任意字段写入 |
| OTA／固件更新 | 已有 BLE／ESB OTA、板型校验和MCUboot路径；ESB v1为60B DATA、66B tracker FW_INFO | 针对Styria MCUboot分区实现ARC8 v2：44B DATA、48B tracker FW_INFO，接收器转换到Helper识别格式；Helper按协议处理并区分待手动重启状态 | 是已有OTA能力的协议／板型适配；需配套两端和Helper，不能混刷。传输CRC通过不等于签名可信，最终由MCUboot验证 |
| 休眠、唤醒与姿态连续性 | 已有WoM、电源策略、retained状态和唤醒路径 | 增加Styria两级启动环境下的保留区安排，以及Earth pair／输出参考状态保存恢复；校准和采集参与休眠抑制 | 是对已有低功耗路径的适配；当前自动深睡仍关闭，受控唤醒通过不等于整夜或续航优于上游 |
| 桌面Helper | 已有设备发现、串口、录制、温度图、VQF回放、校准引导、固件更新和设备预约 | 基于0.4.3扩展五步十台向导、会话文件管理、温表覆盖／开关回读、新旧参数回放、分字段审阅和重复写入核验；新增独立 `calibration/` 运行组件 | 改了已有采集／校准／更新入口的行为，同时增加整组工作流；当前上游为0.4.6，本项目没有完整继承其GUI依赖和发布更新，正常联合流程固定10台 |

## 在这些基础上新增的实验能力

- **十台刚体联合求解**：各台共享角运动，分别估计安装旋转、杆臂及相对时钟；加速度包含切向／向心项。三轴正反转、多姿态静置与转换共同约束比例、g-sens与地球方向。对应 `tools/jointcal/`，不是十次互不关联的单台校准。
- **地球自转／g-sens实验链**：增加参考向量、矩阵存储与设备补偿接口，并接入联合估计和回放。没有在本次上游快照中找到对应的Earth pair／CALWIRE S/M/E整条链；这不代表上游VQF没有地理坐标或零偏估计。
- **F04与CALWIRE闭环**：把采集完整性、参数证据、计划审阅、写入和回读关联起来。现用推荐计划只换比例S，精确保留旧M/E；没有把未通过的Earth候选写成已验收。

## 收益证据应如何读

现有数据支持本项目在特定设备与记录上的行为，不是完整上游固件的性能基准：

| 结果 | 实际对照 | 能得出的结论 |
|---|---|---|
| 回位RMS 5.68879° → 0.73644°，降低87.05% | 同一项目、同批录制、旧参数与只更新S的混合参数 | 支持这批参数的回放改善；拟合使用过这些记录，没有上游整机A/B或外部角度真值 |
| 十台40.5分钟共1,216,480窗，审计零缺口 | 本项目F04现用固件的一次长录制 | 该轮采集完整；不能得出比上游丢包少多少、所有环境零丢包 |
| 单台17段静置漂移指标中位数降低20.08% | 本项目原融合与稳定低通主机原型 | 是数值候选证据；不是已部署固件或当前上游的实机比较 |

温补和g-sens并非所有数据都改善。完整逐台结果见[校准效果](RESULTS_zh.md)，模型迭代、WinError 5、旧F04缺窗等本地问题的修复见[实验记录](EXPERIMENTS_zh.md)和[采集历史](CAPTURE_RELIABILITY_zh.md)。这些修复属于本项目开发历史，不应倒推为上游存在同样缺陷。

## 与当前上游的取舍

上游Tracker已采用NCS v3.4，并包含更多板型、校准模块拆分、加热校准、磁力计及事件生命周期工作；本项目Tracker仍固定NCS v3.1，Receiver固定v3.4。上游Helper 0.4.6的GUI依赖和发布流程也没有整体合入。不能把本项目称为当前上游的功能超集，或把整棵树覆盖升级当成安全合并。

当前适用范围是Styria Mini／R1的实验流程。已有功能的修改、上游修复的移植、本地新扩展及未合入能力，分别以[逐项文件证据](UPSTREAM_DIFF_zh.md)、[融合与温度说明](FUSION_UPSTREAM_zh.md)、[当前状态](STATUS_zh.md)和[待办](ROADMAP_zh.md)为准。
