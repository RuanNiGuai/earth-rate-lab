# F-04 v1 无线摘要与回放

本实现完成 Tracker 原始 IMU → 48 字节 ESB → Receiver HID → Python 回放的代码链路。
实机结果另见 `README.md` 和 `evidence/`；本文件不是多设备精度验收证明。

## 时间与数据含义

- 采集命令：`collectall 50 <已配对槽位>`；省略槽位会选择所有已配对设备，只有实现本协议的 Tracker 才会发摘要。
- 使用传感器实际 `gyro_actual_time` 积分，按 20 ms 相位阈值分配完整样本。409.6 Hz 时窗口包含 8 或 9 点，平均约 50 Hz；每点只进入一个窗口，不插值、不重复。整数纳秒量化误差小于 0.5 ns/样本。
- 单个窗口时长会变化，必须用包内 `duration_us` 解释角增量；不能把每包都视作精确 20 ms。
- 时间从首个 FIFO 数据处理时刻锚定，再按采样间隔重建，标志始终为 `estimated`。它不是硬件采样时间，也不证明设备间同步。
- 陀螺、加速度、温度均在现有校准前取值；输出不是已安装的联合校准结果。加速度均值按每个陀螺采样点计算，包含有限年龄的 hold-last 值，并携带 fresh 计数。
- 可观察到的 FIFO 处理错误会废弃当前窗口、跳过一个窗口序号并重新锚定。无效数值、缺少加速度或采样间隔变化的窗口不发送，但消耗序号。底层驱动未显式报告的样本丢失不能靠此协议证明不存在；保留原始采集作为独立证据。

## 48 字节 ESB 格式

多字节字段均为 little-endian；不能按 C 结构体对齐直接拷贝。

| 偏移 | 长度 | 字段 |
|---|---:|---|
| 0 | 1 | 类型 `0x15` |
| 1 | 1 | Tracker 配对槽位 0–31 |
| 2 | 1 | 协议版本 1 |
| 3 | 1 | 时间质量，固定 `0x01`（estimated） |
| 4 | 4 | 非零启动随机数，来自硬件熵源初始化的 PRNG |
| 8 | 4 | 非零采集轮次，每次成功启动递增 |
| 12 | 4 | 窗口序号，从 0 开始，u32 回绕；无效/队列丢弃也消耗序号 |
| 16 | 4 | 窗口末端估算时间 µs，u32 回绕 |
| 20 | 12 | 三轴角增量，3 × i32，单位微度 |
| 32 | 6 | 三轴平均加速度，3 × i16，单位 mg |
| 38 | 2 | 平均温度，i16，单位 0.01°C |
| 40 | 1 | 窗口内陀螺样本数 |
| 41 | 1 | 对应新加速度标签的样本数；held = 样本数 − fresh |
| 42 | 2 | 窗口实际累计时长，u16，单位 µs |
| 44 | 4 | 对字节 0–43 的 CRC32/IEEE，和 Python `zlib.crc32` 一致 |

CRC 用于检测损坏，不用于身份认证。Receiver 先检查长度、类型、版本、标志、计数、边界及 CRC，再检查目标设备。F-04 不进入原始采集 ARQ/16 位去重或姿态序号路径；PC 负责按会话去重。

同类型、同版本但标志为 `0x02` 的结束清单长度仍为48字节。0–11和44–47的含义相同；12、16、20、24、28、32、36、40依次是u32的：序号上界（不含该序号）、有效窗口、无效窗口、队列溢出、已确认窗口（`submitted`，版本差异见下文）、未排空尾部、发送延后次数、最后不足一窗的样本数。序号上界必须等于有效+无效；有效必须等于已确认窗口+队列溢出+未排空尾部。它不是运动样本，旧接收器/解析器会拒绝，因此须配套更新接收器和宿主工具。

Receiver HID 为 64 字节：0–47 为原包，48 为 i8 RSSI，49–52 为 big-endian 接收端 tick，53–63 为零。接收端 tick 仅保留原始值，不假定 tick 等于毫秒。

## 启停与计数

Tracker使用64项队列，ESB循环每12ms最多完成2次发送；每次都必须取得自己的新时隙。Receiver在批量采集时给每台32 tick宽时隙。F04关闭硬件原地重传；未确认时队首保留到后续时隙重试。只有配置及同步有效才开始累计样本。采集时暂停普通姿态发送，保留PING/控制；其他发送入口与校准入口串行化。

CW5 Tracker／CW4 Receiver的`submitted`表示收到匹配窗口身份的接收器入队确认，仍不能当成PC落盘数。前一版仅表示硬件ACK，更早版本仅表示调用发送接口，不能混用。`queue_drop`和`tail_drop`独立报告。STOP先停止生产，限时排空队列后发送三份相同结束清单，再确认OFF。PC必须同时核验结束清单、窗口序号和接收器停止计数，不能只凭OFF回执断言完整。

## 接收器入队确认（CW5 Tracker／CW4 Receiver）

十台共用七条ESB pipe，硬件ACK没有完整的设备／采集身份。旧代码在`ESB_EVENT_TX_SUCCESS`时直接移除窗口；接收器随后进行校验和入队，无法证明那个窗口确实进入转发队列。硬件CRC／PID去重也不能替代业务序号核对。

新路径在Receiver的RADIO ACK回调中校验F04长度、CRC、物理边界、目标和pipe，并把不可变副本写入HID队列，成功后才返回下列24字节确认。无效、非目标、HID未就绪或队列满时抑制ACK，Tracker保留窗口重试。该回调也处理硬件认为重复的帧，后续ESB事件不再重复转发F04；其他原始采集路径保持自己的处理方式。RADIO与ESB事件的队列生产操作使用同一中断临界区，避免预占时写入同一个槽位。

ACK回调有严格的无线周转时间预算：Tracker的2 Mbit/s底层ACK等待为160 µs，不能把整个3 ms应用等待当成回调可用时间。Receiver使用等价的CRC32字节查表实现；RADIO内仅入队，不调度工作队列。批量采集时由2 ms定时器唤起USB发送，避免调度成本拖迟ACK，且不依赖可能被底层去重省略的ESB事件。已入队条件仍在确认之前，不以移走校验来换取速度。

| 偏移 | 长度 | 确认字段 |
|---|---:|---|
| 0 | 1 | 类型`0x28`，与PONG内的命令标志属于不同字段 |
| 1–15 | 15 | 原帧对应字节：Tracker、版本、窗口／结束标志、启动随机数、采集轮次、窗口序号／结束上界 |
| 16 | 4 | 原帧CRC32，即原帧44–47字节 |
| 20 | 4 | 确认0–19字节的CRC32/IEEE |

Tracker只有在确认CRC及全部身份字段与当前队首完全匹配时才移除该帧。空ACK、其他设备、旧会话、不同序号或不同内容的确认均不会移除窗口。合并的RX事件会排空所有已到达回包；三毫秒内未取得匹配确认则保留原窗口，待无线空闲和下一时隙重试。结束清单遵循相同规则。重传副本仍原样交给主机去重。

普通发送入口持有同一TX互斥锁，因此进入时已没有仍在等待的采集调用。如果最后一次确认超时，入口在无线仍忙时延后，在无线空闲后清理过期等待标志，使PING和姿态能恢复；这不把超时帧计为已确认，也不移除采集队首。离线故障注入覆盖了“最后一次超时且不再调用采集发送”的退出边界。

时隙防重复还必须处理接收器时钟重新起算：若上一时隙的绝对时间比当前估计时间超前超过一个完整帧，判为时钟代际变化，允许在新时钟的合法时隙重新申请；成功申请立即记录新时隙。小于一帧的回退仍保留防重复限制。此项也覆盖接收器32位tick回绕，不提高现有采样时间戳精度。

这项确认保证的是接收器入队，不能保证USB传输或磁盘落盘。队列拒绝单列`F04 admission backpressure`，不冒充已接收后丢弃；USB发送失败及STOP尾部丢弃仍计入`dropped`并导致质量失败。主机零缺口和结束清单门槛继续保留。新Tracker必须配套新Receiver；旧Receiver的空ACK无法让新Tracker通过READY，不做静默降级。

摘要期间维持唤醒，并沿用录制期间的 T-Cal 写入延迟策略。原始采集、摘要和 OTA 不应重叠；切换采集模式须先显式停止并等待 inactive。停止命令重发不会重置会话。

Receiver 停止时继续转发，等目标 Tracker 确认执行 OFF 后至少留 150 ms 排空 USB。7 秒未确认会明确输出未确认位图并结束；队列中被丢弃的报告计入 dropped。此超时不代表目标设备确已停止。

## PC 落盘和回放

`tools/f04_summary.py` 读取专用 `F04HID1` JSONL：首行有格式和接收器 USB 序列号，之后逐行保留主机 monotonic 纳秒时间和完整 64 字节 `report_hex`。不同接收器、Tracker、启动随机数和采集轮次分别统计，不合并。

```powershell
build-env/Scripts/python.exe -B -X utf8 tools/f04_summary.py integration/evidence/<运行>/cycle-1.jsonl --out integration/evidence/<新回放目录>
```

解析器有128窗口乱序缓冲、256窗口近期去重记录；已确认输出范围之外的迟到包单列`late`，不静默修改已报告缺口；冲突重复直接失败。初次观察之前的序号计为`leading_unobserved`，有结束清单时另报`trailing_unobserved`。输出带`time_quality=estimated`和`calibrated=false`。JSONL可包含`capture-stop`收尾行，存储接收器确认及丢弃计数；回放不把它当作样本。

新的开始屏障、零缺口门槛、RAM/Flash容量分析和后续实机步骤，见[采集可靠性](../docs/CAPTURE_RELIABILITY_zh.md)。

`auto_summary_check.py` 是单台自动验收入口，保留两端日志、原始 HID、包哈希、Tracker/Receiver/PC 计数及停止后的 FW_INFO。多设备同时运行、运动精度、遮挡丢包、真实重启和断电仍需实物验收。
